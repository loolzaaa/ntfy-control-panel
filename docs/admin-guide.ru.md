# Руководство администратора

> English version: [Administrator Guide](admin-guide.md).

## 1. Назначение

Веб-панель администрирования ntfy позволяет управлять учётными записями
пользователей ntfy, их токенами доступа и правами на топики. Все изменения
применяются непосредственно к серверу ntfy через его CLI.

Панель предназначена только для администраторов: иных ролей в ней нет.

## 2. Вход в панель

1. Откройте адрес панели в браузере (например, `https://ntfy-admin.example.com`).
2. Введите логин и пароль администратора панели.
3. Нажмите «Войти».

Сессия действует ограниченное время (по умолчанию 8 часов). После нескольких
неудачных попыток вход временно блокируется.

Первичные логин и пароль задаются при развёртывании (см. инструкцию по
развёртыванию). Сразу после первого входа смените пароль.

## 3. Навигация

В верхней части экрана расположены разделы:

- **Пользователи** — основной раздел управления.
- **Журнал аудита** — история действий администраторов.

В правой части шапки — имя администратора, переключатель языка интерфейса
(английский/русский) и кнопки «Сменить пароль» и «Выйти». Выбранный язык
сохраняется в браузере.

## 4. Список пользователей

Раздел «Пользователи» отображает таблицу пользователей ntfy.

| Колонка | Описание |
|---------|----------|
| Имя пользователя | Логин в ntfy. Псевдопользователь `*` помечается как «анонимный». |
| Роль | «Администратор» или «Пользователь». |
| Тариф | Тариф пользователя в ntfy (если задан). |
| Источник | «конфигурация» — пользователь описан в `server.yml`; «вручную» — создан через CLI/панель. |

### Поиск

Поле поиска фильтрует список **по имени пользователя** (подстрока, без учёта
регистра).

### Создание пользователя

1. Нажмите «Создать пользователя».
2. Укажите имя пользователя. Допустимы буквы, цифры и символы `- _ . + @`.
3. Выберите роль в ntfy: «Пользователь» или «Администратор».
4. При необходимости оставьте включённым флажок «Создать и привязать личный
   токен» и задайте метку (по умолчанию — имя пользователя).
5. Нажмите «Создать».

Пароль генерируется автоматически и нигде не отображается — он не используется,
поскольку вход выполняется по токену. Если токен создавался, его значение
показывается **один раз** сразу после создания: скопируйте его и передайте
пользователю. После закрытия окна восстановить значение невозможно — можно лишь
создать новый токен.

### Удаление пользователя

1. Нажмите «Удалить» в строке пользователя.
2. Подтвердите действие.

Вместе с пользователем удаляются все его токены и записи о правах доступа.
Удаление необратимо.

> Кнопка «Удалить» недоступна для псевдопользователя `*` и для пользователей,
> описанных в конфигурации ntfy (`server.yml`) — ими управляет сам ntfy.

## 5. Карточка пользователя

Открывается нажатием на строку или кнопкой «Открыть». Содержит всю информацию и
все действия по пользователю.

### 5.1. Основные сведения

Отображаются имя, роль в ntfy, тариф и признак «Из конфигурации ntfy».

### 5.2. Токены доступа

Таблица токенов содержит значение токена (замаскировано), метку, срок действия и
сведения о последнем доступе.

- **Привязать токен** — укажите метку и, при необходимости, срок действия
  (например, `30d`; пусто — бессрочно), затем нажмите кнопку. Значение нового
  токена показывается один раз.
- **Удалить токен** — кнопка «Удалить» в строке токена.
- **Удалить все токены** — кнопка над таблицей; удаляет все токены пользователя
  одной операцией.

Токены, описанные в конфигурации ntfy, удалить нельзя.

### 5.3. Права доступа к топикам

Таблица «Права доступа к топикам» показывает соответствие «топик → права».

Доступные права:

| Право | Значение |
|-------|----------|
| Только чтение (`read-only`) | Подписка и чтение сообщений топика. |
| Только запись (`write-only`) | Публикация сообщений в топик. |
| Чтение и запись (`read-write`) | Публикация и подписка. |
| Запрет (`deny`) | Доступ к топику запрещён. |

Действия:

- **Назначить** — укажите топик или шаблон и права, нажмите «Назначить».
- **Изменить** — выберите новое значение в выпадающем списке прямо в таблице.
- **Удалить** — кнопка «Удалить» в строке.

Поддерживаются шаблоны топиков с символом `*`, например `alerts-*` — они
обрабатываются средствами ntfy и распространяются на все подходящие топики.

> Для пользователей с ролью «Администратор» права на отдельные топики не
> применяются: администратор ntfy имеет полный доступ ко всем топикам. В карточке
> такого пользователя выводится соответствующее уведомление.

## 6. Журнал аудита

Раздел «Журнал аудита» фиксирует все операции (кто, что, когда).

Фильтры:

- **С даты / По дату** — интервал времени.
- **Администратор** — имя администратора панели.
- **Действие** — тип операции.
- **Пользователь ntfy** — имя целевого пользователя.

Таблица содержит дату и время, администратора, действие, целевого пользователя и
детали операции в формате JSON. Записи выводятся постранично.

Основные типы действий:

| Действие | Описание |
|----------|----------|
| Вход в панель / Неудачная попытка входа / Выход из панели | Аутентификация администратора. |
| Смена пароля администратора | Изменение пароля администратора панели. |
| Создание / Удаление пользователя | Управление учётными записями ntfy. |
| Создание / Удаление токена | Управление отдельными токенами. |
| Удаление всех токенов | Массовое удаление токенов. |
| Назначение / Удаление прав на топик | Управление ACL. |

> Значения токенов в журнале маскируются — в деталях сохраняется только часть
> строки.

## 7. Смена пароля администратора

Нажмите «Сменить пароль» в шапке, укажите текущий и новый пароль (не короче
8 символов) и подтвердите. Пароль администратора панели не связан с паролями
пользователей ntfy.

## 8. Безопасность: рекомендации

- Размещайте панель только за HTTPS (обратный прокси).
- Задайте постоянный `SESSION_SECRET` и `COOKIE_SECURE=true`.
- Ограничьте сетевой доступ к панели (VPN, списки разрешённых адресов).
- Используйте надёжные пароли и меняйте их при смене ответственных.
- Регулярно просматривайте журнал аудита, обращая внимание на неудачные попытки
  входа.
- Не передавайте значения токенов по незащищённым каналам.

## 9. Ограничения

- **Пользователи из конфигурации ntfy** (`server.yml`) недоступны для изменения и
  удаления через панель — ими управляет ntfy.
- **Псевдопользователь `*`** (анонимный доступ) доступен только для просмотра и
  настройки прав на топики; токены для него не создаются.
- **Роль администратора ntfy** не использует права на отдельные топики.
- Панель не хранит пароли пользователей ntfy: при создании пароль генерируется и
  не показывается.

## 10. Аутентификация администраторов панели

Реализована базовая схема — локальные учётные записи администраторов панели с
хешированием пароля (bcrypt). Интеграция с LDAP отнесена к опциональным
требованиям и может быть добавлена как отдельный провайдер аутентификации без
изменения остальной логики панели.
