# Руководство администратора

> English version: [Administrator Guide](admin-guide.md).

## 1. Назначение

Панель управления ntfy позволяет управлять учётными записями
пользователей ntfy, их токенами доступа и правами на топики. Все изменения
применяются непосредственно к серверу ntfy через его CLI.

В панели две роли:

- **Администратор** — полный доступ: пользователи, пароли, токены, права на топики
  и журнал аудита.
- **Пользователь** — личный раздел для работы со своими токенами (создание и
  удаление в пределах настроенного лимита, показ QR-кодов) и для смены пароля
  ntfy. Административные функции ему недоступны.

Администраторы — это локальные учётные записи панели. Пользователи проходят
аутентификацию через внешний провайдер (LDAP) и автоматически получают роль
`user`. Первичный администратор («root») задаётся в конфигурации; остальные
локальные администраторы создаются из панели (см. раздел 7).

## 2. Вход в панель

1. Откройте адрес панели в браузере (например, `https://ntfy-admin.example.com`).
2. Введите логин и пароль (локальной учётной записи панели или LDAP).
3. Нажмите «Войти».

Сессия действует ограниченное время (по умолчанию 8 часов). После нескольких
неудачных попыток вход временно блокируется.

Первичные логин и пароль администратора задаются при развёртывании (см.
инструкцию по развёртыванию). LDAP-пользователи не могут сменить пароль LDAP в
панели — он управляется каталогом, — но могут сменить **пароль ntfy** (см. 5.2 и
раздел 11).

## 3. Навигация

Администраторы видят в верхней части экрана разделы:

- **Пользователи** — основной раздел управления.
- **Администраторы** — локальные учётные записи панели.
- **Журнал аудита** — история действий администраторов.

В правой части шапки — имя пользователя, переключатель языка интерфейса
(английский/русский) и кнопка «Выйти»; локальным администраторам дополнительно
доступна кнопка «Сменить пароль» (у первичного администратора она скрыта — его
пароль управляется конфигурацией). Выбранный язык сохраняется в браузере.

Пользователи с ролью `user` административных разделов не видят: им доступна
страница «Мои токены» для управления своими токенами доступа и смены пароля ntfy.

## 4. Список пользователей

Раздел «Пользователи» отображает таблицу пользователей ntfy.

| Колонка | Описание |
|---------|----------|
| Имя пользователя | Логин в ntfy. Псевдопользователь `*` помечается как «анонимный». |
| Роль | «Администратор» или «Пользователь». |
| Тариф | Тариф пользователя в ntfy (если задан). |
| Источник | «конфигурация» — пользователь описан в `server.yml`; «вручную» — создан через CLI/панель. |

### Поиск

Поле поиска фильтрует список **по имени пользователя** (подстрока, без учёта
регистра).

### Создание пользователя

1. Нажмите «Создать пользователя».
2. Укажите имя пользователя. Допустимы буквы, цифры и символы `- _ . + @`.
3. Выберите роль в ntfy: «Пользователь» или «Администратор».
4. Нажмите «Создать».

Пароль ntfy генерируется автоматически и показывается **один раз** сразу после
создания — текстом и в виде QR-кода. Скопируйте или отсканируйте его и передайте
пользователю: он нужен для входа в клиенты ntfy, не поддерживающие токены
(например, приложение iOS). После закрытия окна восстановить пароль невозможно —
его можно только сбросить. Токены доступа создаются отдельно в карточке
пользователя (см. 5.3).

### Удаление пользователя

1. Нажмите «Удалить» в строке пользователя.
2. Подтвердите действие.

Вместе с пользователем удаляются все его токены и записи о правах доступа.
Удаление необратимо.

> Кнопка «Удалить» недоступна для псевдопользователя `*` и для пользователей,
> описанных в конфигурации ntfy (`server.yml`) — ими управляет сам ntfy.

## 5. Карточка пользователя

Открывается нажатием на строку или кнопкой «Открыть». Содержит всю информацию и
все действия по пользователю.

### 5.1. Основные сведения

Отображаются имя, роль в ntfy, тариф и признак «Из конфигурации ntfy».

### 5.2. Пароль ntfy

Раздел «Пароль ntfy» позволяет управлять паролем, с которым пользователь входит в
клиенты ntfy, не поддерживающие токены (например, приложение iOS).

- **Сгенерировать пароль** — создаёт новый случайный пароль и показывает его один
  раз, текстом и в виде QR-кода.
- **Задать пароль** — введите свой пароль (не короче 8 символов) и нажмите
  «Задать пароль».

Смена пароля не влияет на существующие токены доступа. Пароли пользователей,
описанных в конфигурации ntfy (`server.yml`), изменить нельзя.

### 5.3. Токены доступа

Таблица токенов содержит значение токена (замаскировано), метку, срок действия и
сведения о последнем доступе.

- **Привязать токен** — укажите метку и, при необходимости, срок действия
  (например, `30d`; пусто — бессрочно), затем нажмите кнопку. Значение нового
  токена показывается один раз. У каждого пользователя может быть не более
  `MAX_TOKENS_PER_USER` токенов (по умолчанию 4); при достижении лимита кнопка
  недоступна.
- **QR-код** — кнопка «QR-код» открывает сканируемый код с токеном для быстрого
  переноса в мобильное приложение ntfy.
- **Удалить токен** — кнопка «Удалить» в строке токена.
- **Удалить все токены** — кнопка над таблицей; удаляет все токены пользователя
  одной операцией.

Токены, описанные в конфигурации ntfy, удалить нельзя.

### 5.4. Права доступа к топикам

Таблица «Права доступа к топикам» показывает соответствие «топик → права».

Доступные права:

| Право | Значение |
|-------|----------|
| Только чтение (`read-only`) | Подписка и чтение сообщений топика. |
| Только запись (`write-only`) | Публикация сообщений в топик. |
| Чтение и запись (`read-write`) | Публикация и подписка. |
| Запрет (`deny`) | Доступ к топику запрещён. |

Действия:

- **Назначить** — укажите топик или шаблон и права, нажмите «Назначить».
- **Изменить** — выберите новое значение в выпадающем списке прямо в таблице.
- **Удалить** — кнопка «Удалить» в строке.

Поддерживаются шаблоны топиков с символом `*`, например `alerts-*` — они
обрабатываются средствами ntfy и распространяются на все подходящие топики.

> Для пользователей с ролью «Администратор» права на отдельные топики не
> применяются: администратор ntfy имеет полный доступ ко всем топикам. В карточке
> такого пользователя выводится соответствующее уведомление.

## 6. Журнал аудита

Раздел «Журнал аудита» фиксирует все операции (кто, что, когда).

Фильтры:

- **С даты / По дату** — интервал времени.
- **Администратор** — имя администратора панели.
- **Действие** — тип операции.
- **Пользователь ntfy** — имя целевого пользователя.

Таблица содержит дату и время, администратора, действие, целевого пользователя и
детали операции в формате JSON. Записи выводятся постранично.

Основные типы действий:

| Действие | Описание |
|----------|----------|
| Вход в панель / Неудачная попытка входа / Выход из панели | Аутентификация администратора. |
| Смена пароля администратора | Изменение собственного пароля администратора панели. |
| Создание / Удаление / Смена пароля администратора панели | Управление локальными учётными записями панели. |
| Создание / Удаление пользователя | Управление учётными записями ntfy. |
| Смена пароля ntfy | Изменение или сброс пароля пользователя ntfy (значение не журналируется). |
| Создание / Удаление токена | Управление отдельными токенами. |
| Удаление всех токенов | Массовое удаление токенов. |
| Назначение / Удаление прав на топик | Управление ACL. |

> Значения токенов в журнале маскируются — в деталях сохраняется только часть
> строки.

## 7. Администраторы панели

Раздел «Администраторы» содержит список локальных учётных записей панели.

- **Создать администратора** — укажите имя; оставьте пароль пустым для генерации
  (показывается один раз, с QR-кодом) или задайте свой пароль (не короче
  8 символов). Передайте учётные данные человеку.
- **Пароль** — сбросить пароль администратора (сгенерировать или задать свой).
- **Удалить** — удалить администратора.

**Первичный администратор** («root») задаётся в конфигурации
(`BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD`) и помечается бейджем
«Первичный». Его нельзя удалить или сбросить пароль из панели: пароль всегда
синхронизируется с конфигурацией и меняется только правкой конфигурации и
перезапуском панели. Он предназначен для создания остальных администраторов.

## 8. Смена своего пароля администратора панели

Дополнительные (не первичные) администраторы могут нажать «Сменить пароль» в
шапке, указать текущий и новый пароль (не короче 8 символов) и подтвердить.
Меняется только **пароль панели**; пароли пользователей ntfy управляются в
карточке пользователя (см. 5.2) и на странице «Мои токены». У первичного
администратора этой кнопки нет — его пароль управляется конфигурацией (см.
раздел 7).

## 9. Безопасность: рекомендации

- Размещайте панель только за HTTPS (обратный прокси).
- Задайте постоянный `SESSION_SECRET` и `COOKIE_SECURE=true`.
- Ограничьте сетевой доступ к панели (VPN, списки разрешённых адресов).
- Используйте надёжные пароли и меняйте их при смене ответственных.
- Регулярно просматривайте журнал аудита, обращая внимание на неудачные попытки
  входа.
- Не передавайте значения токенов по незащищённым каналам.

## 10. Ограничения

- **Первичного администратора панели** нельзя удалить или сменить ему пароль
  через панель; он управляется конфигурацией.
- **Пользователи из конфигурации ntfy** (`server.yml`) недоступны для изменения и
  удаления через панель — ими управляет ntfy.
- **Псевдопользователь `*`** (анонимный доступ) доступен только для просмотра и
  настройки прав на топики; токены для него не создаются.
- **Роль администратора ntfy** не использует права на отдельные топики.
- Панель не хранит пароли пользователей ntfy: при создании пароль генерируется,
  показывается один раз и передаётся в ntfy. Его можно только сбросить, но не
  восстановить.

## 11. Аутентификация пользователей панели

Аутентификация выполняется провайдерами, которые включаются и упорядочиваются
параметром `AUTH_PROVIDERS` (например `local,ldap`). Провайдеры перебираются в
порядке конфигурации:

- **local** — учётные записи в базе панели (хеши bcrypt). Это администраторы.
- **ldap** — привязка к каталогу LDAP. LDAP-пользователи получают роль `user`.

При первом успешном LDAP-входе ntfy-пользователь может быть создан автоматически
(со случайным паролем и без токенов), если задан `LDAP_PROVISION_NTFY_USER=true`.

LDAP-пользователи могут сменить **пароль ntfy** на странице «Мои токены» (он нужен
клиентам ntfy, не поддерживающим токены). **Пароль LDAP** управляется каталогом и в
панели изменить его нельзя.

## 12. API интеграции (автоматизация)

Для машинных клиентов (например n8n) панель может предоставить небольшой API с
bearer-токеном для создания пользователей ntfy и их прав на топики. Он выключен,
пока в `.env` панели не задан `INTEGRATION_API_KEYS`:

```dotenv
INTEGRATION_API_KEYS=n8n:npk_<случайное значение>
```

Сгенерировать ключ:

```bash
node -e "console.log('npk_' + require('crypto').randomBytes(32).toString('hex'))"
```

Эндпоинты (заголовок `Authorization: Bearer <ключ>`):

- `POST /api/integration/users` — тело:

  ```json
  {
    "username": "alice",
    "role": "user",
    "password": "необязательный-свой-пароль",
    "acls": [{ "topic": "alerts-*", "permission": "read-write" }]
  }
  ```

  Если `password` не указан, панель сгенерирует его. Ответ содержит имя
  пользователя и пароль (показывается один раз):

  ```json
  { "user": { "name": "alice", "role": "user" }, "password": "...", "acls": [] }
  ```

- `PUT /api/integration/users/:username/access` — тело
  `{ "topic": "...", "permission": "read-only" }`.
- `DELETE /api/integration/users/:username/access?topic=...`.

Значения прав: `read-only`, `write-only`, `read-write`, `deny`. В топике
допустим `*`.

Примечания:

- Ключ API — секрет: храните его только в `.env` панели и в клиенте. Все вызовы
  пишутся в журнал аудита под именем `api:<имя>`.
- Изменения `INTEGRATION_API_KEYS` вступают в силу только после перезапуска
  панели; замена ключа делает старый недействительным сразу после перезапуска.
- Панель не хранит и не возвращает публичный адрес ntfy-сервера — держите его в
  конфигурации клиента.
